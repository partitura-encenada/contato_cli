# Contato CLI

[![pt-br](https://img.shields.io/badge/lang-pt--br-green.svg)](README.md)

CLI for interfacing with the **Contato** system, developed at the Federal University of Rio de Janeiro (UFRJ) in partnership with the UFRJ Technology Park 🎶🖥️

## Content

* 🖥️ Requirements
* ➕ Additional dependencies
* 🪛 Installation
* ❓ Usage
* 🎼 Performance Files (JSON)
* 📁 Project Structure
* 📌 Project Management

### Requirements 🖥️

* Windows 8 or newer.
* Python 3.12.7.
* Bluetooth 4.2 BLE or newer.

### Additional Dependencies ➕

Some features require external software for creating virtual MIDI ports.

The use of **loopMIDI** is recommended for integration with DAWs and virtual instruments.

### Installation 🪛

In your terminal, run:

```bash
pip install contato-cli
```

For development:

```bash
pip install -e .
```

The `-e` option installs the project in editable mode, allowing code changes to be reflected immediately.

### Usage ❓

All commands are prefixed with:

```bash
contato
```

To obtain help:

```bash
contato --help
```

or

```bash
contato <command> --help
```

## Command summary

| Command | Purpose |
|---|---|
| `scan-com` | Finds which COM port each base is on |
| `connect` | Plays a performance (sensors → MIDI) |
| `ota` | Flashes firmware to an equip, base or TDMA over the air (via the bridge) |
| `update-bases` | Flashes firmware to several bases at once over USB |
| `calibrate` | Calibrates an equip's MPU6050 and prints the offsets |
| `monitor` | Logs the radio channel quality (with `monitor.cpp`) |
| `diag-6dof` | Diagnostics: shows the 6 axes of `equip_6DOF` |
| `scan-mac` | Legacy: does not work with the current firmware |

## scan-com

Looks for bases connected over USB: sends `ID?` on each port and records who answers `ID/<n>`. The result is saved to `com_contato_dict.py`, which the other commands use to find the port from the ID:

```text
Base ID ↔ COM Port
```

Usage:

```bash
contato scan-com
contato scan-com --timeout 2
```

| Option | Description |
|---|---|
| `--timeout` | Seconds to wait for an answer on each port (default 1) |

Example:

```text
ID 5 encontrado em COM8
ID 6 encontrado em COM9
Arquivo atualizado: ...\com_contato_dict.py
2 ID(s) encontrado(s): 5, 6
```

`com_contato_dict.py` stays on your computer only (it is not in git). If it does not exist, the CLI creates an empty one on start.

Run this command when you:

* connect new bases;
* change USB ports;
* restart the computer.

## connect

Starts a performance: resets the base, sends `START`, reads the sensors and plays MIDI. On Ctrl+C it sends `STOP` and turns the notes off.

Usage:

```bash
contato connect <performance> --id <id>
contato connect <performance> --com <port>
```

| Option | Description |
|---|---|
| `<performance>` | Name of the JSON in `repertorio/` (without `.json`) |
| `--id` | Base ID (port taken from `com_contato_dict.py`) |
| `--com` | COM port number, instead of `--id` (e.g. `8`) |
| `--daw` / `--no-daw` | Uses virtual MIDI ports for the DAW (on by default) |

Example:

```bash
contato connect paixao_vidro_e --id 5
```

### Simultaneous execution

Several performances can run at the same time, one per terminal:

```bash
# Terminal 1
contato connect paixao_vidro_e --id 5

# Terminal 2
contato connect paixao_vidro_d --id 6
```

## ota

Builds a firmware from [contato_hardware](../contato_hardware) and flashes it over the air, without a cable. The PC sends the file to the **bridge** (an ESP32 running `ponte.cpp` on USB), which forwards it to the device over ESP-NOW and confirms each step.

Usage:

```bash
contato ota --id 3 --port COM7                          # flashes equip_3
contato ota --base 4 --port COM7                        # flashes base_4
contato ota --tdma --port COM7                          # flashes the TDMA master
contato ota --id 6 --script equip_6DOF --port COM7      # flashes another script to equip 6
```

| Option | Description |
|---|---|
| `--id` | Equip ID (MAC in `equip_mac_dict.py`); flashes `equip_<id>` |
| `--base` | Base ID (MAC in `base_mac_dict.py`); flashes `base_<id>` |
| `--tdma` | Flashes the TDMA master (MAC in `TDMA_MAC`, in `over_the_air.py`) |
| `--script` | Flashes another script instead of the default (e.g. `equip_6DOF`) |
| `--port` | Bridge serial port (required) |

## update-bases

Flashes `base_<id>.cpp` over **USB** to several bases at once. Uses `com_contato_dict.py` (generated by `scan-com`) to find each ID's port and prints a summary at the end.

Usage:

```bash
contato update-bases --ids 3,4,5,6
contato update-bases --ids 3-8
contato update-bases --ids 3,5-8,10
```

## calibrate

Calibrates an equip's MPU6050 over the air:

1. Builds `util/calibrate.cpp` and flashes it to the equip through the bridge (like `ota`).
2. The equip restarts in the calibration firmware. **Lay the equip flat and still, sensor facing up, and touch the touch sensor**: calibration only starts on touch. You have up to 60 s.
3. In ~15–20 s the equip sends the offsets back through the bridge, and the command prints lines ready to paste into `equip_<id>.cpp`:

```text
    mpu.setXAccelOffset(-1996);
    ...
```

4. Paste the values into `equip_<id>.cpp` and flash the normal firmware again (`contato ota --id <id> ...`). Until then the equip stays on the calibration firmware.

Usage:

```bash
contato calibrate --id 3 --port COM7
```

| Option | Description |
|---|---|
| `--id` | Equip ID |
| `--port` | Bridge serial port |

## monitor

Logs what `monitor.cpp` (an ESP32 that only listens to channel 11) measures on the radio: channel occupancy, TDMA beacons, losses, retries and delay for each equip, external sources and nearby Wi-Fi networks.

Usage:

```bash
contato monitor
contato monitor --port COM7 --folder logs_monitor --quiet
```

| Option | Description |
|---|---|
| `--port` | Monitor port; if omitted, it is found automatically (skipping the bases) |
| `--folder` | Log folder (default `logs_monitor`) |
| `--quiet` | Does not print the status line every second |

How it works:

1. Looks for the monitor: sends `ID?` on the ports (except the bases') and waits for `ID/MONITOR` or a data line.
2. Creates `logs_monitor/monitor_YYYYMMDD_HHMMSS.csv`, with a header describing the columns.
3. Writes each line with the PC time. Every second it saves the file and prints a status line.
4. When the monitor is turned off or sends nothing for 5 s, it writes a **summary with indicators** at the end of the file (`[!]` points to the problem and the candidate fix) and closes the file.
5. Goes back to searching: every time the monitor is turned on a new file is created. Ctrl+C exits, closing the log with the summary.

## diag-6dof

Diagnostics **separate from `connect`** (plays no MIDI) to read `equip_6DOF` through `base_6DOF`. Shows the 6 axes already converted to physical units, on a line refreshed 10 times per second, along with how many messages per second are arriving.

Usage:

```bash
contato diag-6dof --id 6
contato diag-6dof --port COM7 --output test.csv
```

| Option | Description |
|---|---|
| `--id` | base_6DOF ID (port from `com_contato_dict.py`) |
| `--port` | Base port, instead of `--id` |
| `--output` | CSV file to record every line (optional) |

Screen example:

```text
E6 [brutos] giro  X  10.0  Y  -20.0  Z  0.0 graus/s | accel X 0.00  Y 0.00  Z 1.00 g | toque 1 | 111 msg/s
```

| Mode | Rotation | Acceleration |
|---|---|---|
| `[brutos]` (raw) | gyroscope in degrees/s (value ÷ 16.4) | accelerometer in g, with gravity (÷ 16384) |
| `[tratados]` (processed) | yaw/pitch/roll in degrees | linear acceleration in g, without gravity (÷ 8192) |

The mode is selected in the equip firmware (`RAW_DATA`); see the *6DOF Equip and Base* section of the contato_hardware README. On Ctrl+C the command sends `STOP` and prints how many lines it received. The CSV keeps the unconverted values: `pc,id,modo,rot_x,rot_y,rot_z,acc_x,acc_y,acc_z,touch`.

## scan-mac (legacy)

Asked the base to discover and save the equip MAC (`DISCOVER`). **The current firmware no longer does this**: the equip MAC is fixed in `base_<id>.cpp`. The command is still in the CLI, but gets no answer.

# Performance Files (JSON) 🎼

Each performance is defined by a JSON file.

Example:

```json
{
  "gyro_notes": ["C4", "E4", "G4"],
  "accel_notes": ["C2"],
  "gyro_sensitivity": 300,
  "accel_sensitivity_+": 1500,
  "accel_sensitivity_-": 1500,
  "accel_delay": 0.5,
  "legato": true,
  "modo_gate": false
}
```

## Fields

### gyro_notes

Notes associated with the gyroscope.

Example:

```json
"gyro_notes": ["C4", "E4", "G4"]
```

---

### accel_notes

Notes associated with the accelerometer.

Example:

```json
"accel_notes": ["C2"]
```

---

### gyro_sensitivity

Gyroscope sensitivity.

Lower values make the system more sensitive.

---

### accel_sensitivity_+

Positive acceleration threshold.

Example:

```json
"accel_sensitivity_+": 1500
```

---

### accel_sensitivity_-

Negative acceleration threshold.

Example:

```json
"accel_sensitivity_-": 1500
```

---

### accel_delay

Minimum time between consecutive triggers.

Example:

```json
"accel_delay": 0.5
```

Equivalent to 500 ms.

---

### legato

Controls whether previously played notes should be stopped before new notes are played.

Example:

```json
"legato": true
```

When enabled:

```text
New note → stops previous note
```

---

### modo_gate

Enables continuous accelerometer-based behavior.

Example:

```json
"modo_gate": true
```

Behavior:

```text
Acceleration below threshold
→ note remains playing

Acceleration above threshold
→ note stops

Acceleration returns below threshold
→ note plays again
```

If the field is absent:

```json
"modo_gate": false
```

is assumed automatically, preserving compatibility with older performances.

## System Architecture

```text
Sensor Unit (ESP32)
        ↓ ESP-NOW
Base (ESP32 USB)
        ↓ Serial
Contato CLI
        ↓ MIDI
DAW / Virtual Instruments
```

## Project Structure 📁

```text
contato_cli
├── dist
├── src/contato_cli
│ ├── repertorio
│ ├── util
│ ├── __init__.py
│ ├── __main__.py           # command group, scan-com, scan-mac and connect
│ ├── player.py             # sensors → MIDI
│ ├── over_the_air.py       # ota
│ ├── update_bases.py       # update-bases
│ ├── calibrate.py          # calibrate
│ ├── monitor.py            # monitor
│ ├── diagnostic_6dof.py    # diag-6dof
│ └── *_dict.py             # COM ports and MACs of equips and bases
├── tests
├── LICENSE
├── pyproject.toml
└── README.en.md
```

### repertorio

JSON files containing performance configurations.

### util

Utility scripts.

### **main**.py

Application entry point.

### player.py

Class responsible for interpreting sensor data and generating MIDI events.
